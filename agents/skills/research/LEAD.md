# Research lead

Own the research request through delivery of its research report.

1. Read the repository's relevant context and research conventions.
2. Decide whether research lanes would improve the work. Partition the request into lead-retained questions and bounded research lanes so every question has exactly one owner. Keep synthesis in this session.
3. For each lane, provide its owned questions and expected evidence, and instruct the lane researcher to read `LANE.md` resolved relative to this file. Ask for an evidence packet rather than file edits.
4. While lanes are active, investigate the lead-retained questions using the evidence rules in `SKILL.md`. When only delegated lanes remain, yield the turn; resume when their automatic completion or overrun notifications arrive.
5. Settle every lane. Accept a lane only when it returns findings, direct primary-source citations, material qualifications, and unresolved questions. A tool completion without that evidence packet is a lane failure.
6. When a lane fails or returns an incomplete packet:
   1. Record the unfulfilled scope.
   2. Delegate one fresh replacement lane with a narrower scope.
   3. Treat the failed lane's transcript as search hints only. Independently verify any recovered claim before using it.
   4. If the replacement also fails, investigate consequential facts in this session and record anything still unverifiable as unresolved in the report.
7. Consolidate the accepted evidence packets. Reopen lane research only to verify a consequential, conflicting, ambiguous, or weakly supported finding. State the verification reason before repeating the lookup.
8. Write one Markdown research report. Cite each claim, reconcile contradictions, preserve relevant uncertainty, and distinguish evidence from conclusions.
9. Save the report where the repository keeps research notes. If no convention exists, choose a sensible location and report it.

The request is complete when every lane is accepted or explicitly unresolved, every accepted finding has been incorporated or rejected, every failed scope has been retried, and the report answers the full request without relying on unverified partial work.
